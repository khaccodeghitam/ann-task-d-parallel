# D1 observability gap — G0 source audit

**NO.** The current tracer cannot validly distinguish dependency starvation from all of I/O waiting, FIFO-hidden completion, published-but-not-calc-ready state, and ready work that was not selected. This conclusion follows from the event contract and exact source, independently of the halted G0 campaign. No D1 instrumentation or policy is implemented here.

A minimal future state model would explicitly maintain disjoint candidate and request populations: known-unissued eligible candidates; selected-but-not-submitted; submitted-not-CQE; CQE-hidden; published/search-visible; unvisited calc-ready candidates; selected-for-expansion; expanded/evicted. Candidate state and request state are different: not every published request must expand, and a published node may fall outside the active candidate pool.

`next_read_nbr`, `next_calc_nbr`, and `frontier` mutate selection/marker state. Never invoke them a second time merely to inspect readiness. Future counters should observe existing transitions/results, validate candidate conservation and record sampling/overhead before drawing starvation conclusions. This document proposes measurement hooks only; none are added by Issue #8.

Low inflight is insufficient evidence of dependency starvation. Host locking, candidate eligibility, CPU scheduling, unobserved CQEs, publication, and selection can produce similar traces. A future D1 test needs these missing states plus a controlled protocol; G0 does not supply that test.
